ProximiioMap embeds the native map view of each platform: the iOS map view controller and the Android map view. Flutter composes it with the widgets around it.

Creation

  1. The widget sends its MapOptions to the plugin and gets a handle.
  2. It creates the platform view with that handle. The native side builds the map with the options and the process-wide SDK instance.
  3. onMapCreated receives the controller for that map.

Without an SDK instance (no Proximiio.create yet) the platform view shows a notice, every controller call throws MapErrorCode.notConfigured, and cameraReady fails with it.

Gestures

By default the map takes every gesture, so panning and zooming work inside scroll views. Pass gestureRecognizers to share gestures with the widgets around it.

Composition

PlatformHow
iOSA UIKit platform view. The map's view controller joins the app's view controller hierarchy, which the map needs for safe areas.
AndroidTexture-layer composition. The map renders to a TextureView while MapOptions.backgroundColor is not opaque (the default). An opaque backgroundColor renders to a SurfaceView, which Flutter composes in a slower mode.

Lifecycle

On Android the map follows the activity's lifecycle (pause, resume). On iOS it follows its view controller. Removing the widget disposes the native map and ends a running journey, also when the platform view was never created. After a hot restart the first new map releases the maps of the previous run.

Several maps

Each ProximiioMap has its own controller and native map. All of them show the same SDK instance.
